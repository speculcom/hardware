Work back from memory requirement to hardware

The order is: work out how much memory is needed, then whether it fits, and only then look at compute and power. Each step gives the criterion, not a recommendation; use the formulas on the models site for the memory sum, since this site only covers the device side.

  1. 1. First fix the memory requirement — weights, KV cache and framework overhead together. No device enters the picture yet. entry
  2. 2. If the requirement is within 24 GB and a single machine is enough, read the consumer card's memory and system power requirement. entry
  3. 3. For the 48 GB tier under sustained load or side-by-side installation, read the workstation card with ECC memory and a 300 W envelope. entry
  4. 4. At the 80 GB tier, establish whether it is SXM or PCIe — their interconnect capability differs by an order of magnitude. entry
  5. 5. Above 80 GB, compare capacity and bandwidth, and check whether the power ceiling exceeds what the facility can supply. entry
  6. 6. If one card is not enough and eight-way fabric is required, check the NVSwitch topology on-premises or the card count and network per instance in the cloud. entry
  7. 7. For running on a robot body, first check whether unified memory is sufficient, then whether power fits the battery and thermal envelope. entry
  8. 8. For vision inference only, without a language model, a low-power accelerator module matches the compute and power tier better. entry
  9. 9. Finally verify power and site conditions: board power, system supply, chassis airflow and operating temperature. If any one fails, the design goes back a step. entry
